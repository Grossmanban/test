# Синхронизация между устройствами (Supabase)

Без этой настройки «Домашняя бухгалтерия» хранит записи только на одном устройстве.
Чтобы видеть одни и те же записи на iPhone, iPad и компьютере, подключите свой
бесплатный проект [Supabase](https://supabase.com) — это облачная база данных.
Проект принадлежит только вам, и каждый вошедший пользователь видит только свои записи.

Займёт около 10 минут. Понадобится электронная почта.

## 1. Создайте проект

1. Откройте <https://supabase.com/dashboard> и войдите (через GitHub или по почте).
2. Нажмите **New project**.
   - **Name**: `budget` (любое).
   - **Database Password**: нажмите **Generate a password** и сохраните пароль в менеджер паролей.
     Приложению он не нужен.
   - **Region**: ближайший к вам, например *Central EU (Frankfurt)*.
   - План **Free**. Остальное оставьте по умолчанию (Data API должен быть включён).
3. Нажмите **Create new project** и подождите 1–2 минуты.

## 2. Создайте таблицы

1. В меню слева откройте **SQL Editor** и нажмите **New query** (или «+»).
2. Откройте файл [`supabase/schema.sql`](https://github.com/Grossmanban/test/blob/main/supabase/schema.sql),
   нажмите кнопку **Copy raw file** (значок копирования над текстом) и вставьте текст в редактор.
3. Нажмите **Run**. Если Supabase предупредит о «destructive operation», нажмите
   **Run this query**: скрипт пересоздаёт только правила доступа и проверки значений, записи он не трогает.
4. Должно появиться **Success. No rows returned**.

Проверка: в **Table Editor** есть таблицы `transactions` и `budget_settings`, и рядом с ними
нет пометки **Unrestricted** (значит, защита RLS включена).

Скрипт можно запускать повторно, например после обновления приложения. Данные сохранятся.

## 3. Настройте вход по почте

**Authentication → Sign In / Providers** (в старых версиях панели: **Providers → Email**).

- **Email** должен быть включён (так по умолчанию).
- **Confirm email**: выберите один из двух вариантов.

| | Включено (по умолчанию) | Выключено |
|---|---|---|
| Регистрация | приходит письмо со ссылкой, войти можно после подтверждения | сразу, без письма |
| Минус | встроенная почта Supabase отправляет около 2 писем в час и только на адреса участников вашей организации в Supabase, то есть на ваш собственный адрес. Для других адресов нужен свой почтовый сервер: **Authentication → Emails → SMTP Settings** | адрес не проверяется: если ошиблись в адресе, восстановить пароль по почте не получится |

Для себя и семьи проще всего так: выключите **Confirm email**, зарегистрируйте в приложении
все нужные аккаунты, а потом на той же странице выключите **Allow new users to sign up**.
Тогда никто посторонний не сможет создать аккаунт в вашем проекте.

Ссылки из писем (подтверждение, сброс пароля) на iPhone откроются в Safari, а не в
установленном приложении. Это нормально. Ссылка подтверждения просто подтверждает адрес;
ссылка сброса пароля откроет форму нового пароля. Если адрес проекта и ключ вводились
только в приложении (вариант Б в шаге 6), Safari один раз попросит их ввести: у Safari
свои данные. Сама ссылка в аккаунт не входит, если в этом браузере вы в него ещё
не входили. Потом вернитесь в приложение с экрана «Домой» и войдите с почтой и паролем.
Если открылась форма нового пароля, а смену пароля вы не запрашивали, нажмите в ней **Отмена**:
пароль останется прежним.

## 4. Укажите адрес сайта

**Authentication → URL Configuration**:

- **Site URL**: `https://grossmanban.github.io/test/` → **Save**.
- **Redirect URLs** → **Add URL**: `https://grossmanban.github.io/test/**` → **Save**.

Без этого ссылки из писем ведут на `localhost:3000` и не открываются.

## 5. Скопируйте адрес проекта и ключ

- **Project URL**: значок шестерёнки **Project Settings → Data API**, адрес вида
  `https://abcdefgh.supabase.co`. Его же показывает кнопка **Connect** вверху страницы проекта.
- **Ключ**: **Project Settings → API Keys** → **Publishable key** (начинается с `sb_publishable_`) → **Copy**.
  Если там только старые ключи, откройте вкладку **Legacy API keys** и скопируйте ключ
  **anon** / **public** (начинается с `eyJ`). Подходит любой из двух.

> **Этот ключ публичный по замыслу.** Он попадает в код сайта, и его может увидеть любой,
> кто откроет страницу. Ключ только позволяет обратиться к проекту. Читать и менять записи
> можно лишь после входа и только свои: это обеспечивают правила RLS из `schema.sql`.
>
> **Никогда не используйте ключ `service_role` или Secret key (`sb_secret_…`).** Он обходит
> все правила и даёт полный доступ ко всем данным. Не вставляйте его ни в `config.js`, ни
> в приложение, ни в переписку. Если он всё-таки утёк, удалите его и создайте новый на той
> же странице **API Keys**.

## 6. Подключите приложение

**Вариант А: сразу для всех устройств.** Адрес и ключ записываются в файл `config.js`
на GitHub.

1. Откройте [`config.js`](https://github.com/Grossmanban/test/blob/main/config.js) и нажмите
   карандаш (**Edit this file**).
2. Впишите свои значения в кавычки:

   ```js
   window.BUDGET_CONFIG = {
     supabaseUrl: "https://abcdefgh.supabase.co",
     supabaseAnonKey: "sb_publishable_..."
   };
   ```

3. Нажмите **Commit changes…** → **Commit changes**. Через 1–2 минуты сайт обновится:
   во вкладке **Actions** появится зелёная галочка. Откройте приложение, и если оно
   предложит обновиться, согласитесь.

**Вариант Б: только на одном устройстве.** В приложении откройте окно синхронизации
(значок облака в верхней панели), вставьте адрес проекта и ключ и сохраните. Повторите это на
каждом устройстве.

## 7. Войдите

На первом устройстве откройте в приложении окно синхронизации (значок облака вверху), выберите **Создать аккаунт** (почта и пароль не короче
6 символов), при необходимости подтвердите почту и войдите. На остальных устройствах
войдите с той же почтой и паролем. Записи появятся везде. Без интернета приложение
продолжает работать, а изменения отправятся, когда связь появится.

## Полезно знать

- **Проект «уснул».** Если неделю никто не открывал приложение, бесплатный проект
  приостанавливается. Данные сохранятся, и приложение будет работать офлайн. Откройте
  <https://supabase.com/dashboard> и нажмите **Restore project**.
- **Удалить аккаунт со всеми записями**: **Authentication → Users** → «⋯» у пользователя →
  **Delete user**. Его записи удалятся автоматически.
- **Резервная копия**: в окне синхронизации кнопка **Сохранить копию** (файл JSON), восстановление через **Загрузить копию**. Хранить её стоит и при включённой
  синхронизации.

| Что видно | Что сделать |
|---|---|
| «Invalid API key» | ключ скопирован не целиком или это не тот ключ (шаг 5) |
| «relation … does not exist» или «permission denied» | не выполнен шаг 2: запустите `schema.sql` |
| Ссылка из письма открывает `localhost` | шаг 4 |
| Ссылка из письма открыла сайт, а не форму пароля | укажите адрес проекта и ключ в открывшемся окне (шаг 5), как в приложении |
| Письмо не пришло | лимит около 2 писем в час или адрес не из вашей организации (шаг 3) |
